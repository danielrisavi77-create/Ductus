# Pisac u oblaku: postupak

Zajednički postupak pisca u oblaku (Backend, Frontend, Platforma); zadatak sadrži samo opseg i upućuje ovamo. Izvor: vlasnička odluka na #87 od 2. 11. 2026. Gate i pravila se ne mijenjaju; u sukobu vrijede kanonski dokumenti (`README.md`). `<slot>` i `<DAN-xxx>` su slot i Linear oznaka iz zadatka, `<repo>` je danielrisavi77-create/Ductus.

## GitHub u oblaku: samo REST
U oblaku je GitHub GraphQL blokiran (HTTP 403), pa `gh auth status`, `gh pr view|list|checks|edit|ready|create`, `gh issue comment` i `gh api graphql` padaju s lažnom porukom da je token nevažeći; zato koristi samo `gh api repos/<repo>/...`. Prva naredba: `node -v && pnpm -v && gitleaks version && test -d node_modules/cc-safety-net && gh api repos/<repo> --jq .full_name`; ako padne, BLOK „okruženje” na #1091. Rute: komentar `issues/<n>/comments -F body=@datoteka`, novi PR `-X POST pulls`, opis `-X PATCH pulls/<n>`, CI `commits/<head>/check-runs?per_page=100` i statusi (gate) `commits/<head>/status`, PR-ovi za ticket `search/issues?q=repo:<repo>+is:pr+<DAN-xxx>`, niti `pulls/<n>/ccr/review_threads` (polje `resolved`; `<id>` je prvi iz `comment_ids`) i razrješenje `-X POST pulls/<n>/ccr/comments/<id>/resolve`, `-X POST pulls/<n>/ccr/ready_for_review` i `-X POST pulls/<n>/ccr/convert_to_draft` (bez `-X POST` `gh api` šalje GET).

## Postupak
1. Prvo provjeri na mainu što je već napravljeno (grep, git log, otvoreni PR-ovi: `gh api 'search/issues?q=repo:<repo>+is:pr+<DAN-xxx>'`). Ako je već gotovo, javi to i završi.
2. Ugovor prije koda: kratak komentar na issue #1091 (format `OBLAK <slot> · UGOVOR`) s opsegom, datotekama i testovima. Najviše ~400 promijenjenih redaka po PR-u; veće podijeli. Ugovor obavezno sadrži (Daniel 2. 11. 2026., #87): (a) kod zaštita, guardova, parsera i skenera izričit popis klasa ulaza koje se pokrivaju i tablični ili svojstveni (fast-check) test nad svim klasama, napisan prije koda; (b) kod sesija, migracija i baze redak „Istodobnost:” (što se događa kad se stanje promijeni između dva čitanja ili dvije transakcije rade istodobno) s negativnim testom; ako ništa od toga ne vrijedi, napiši „ne primjenjuje se” i zašto. **Nakon ugovora ili pitanja nemoj završiti sesiju.** Sesija se gasi čim prestaneš raditi i tada više ne vidi odgovor. Na potvrdu ugovora NE čekaj (bez `sleep`): odmah nastavi s kodom na svojoj grani i u nacrtu PR-a. Odgovor orkestratora (`claude:b:orchestrator`) na #1091 pročitaj između koraka rada i obavezno prije SPREMAN, pa primijeni ispravak ako ga ima. Zatim zasebnim pozivom pročitaj nove komentare. CI prati ponovljenim jednokratnim provjerama (`gh api 'repos/<repo>/commits/<head>/check-runs?per_page=100'` i `gh api repos/<repo>/commits/<head>/status`) između drugog rada, bez sleepa. Ne završavaj potez dok čekaš. Ponavljaj to najviše 60 minuta. Ako ugovor do SPREMAN nije potvrđen, ipak objavi SPREMAN i u njemu napiši da potvrda ugovora nije stigla; BLOK zbog čekanja ne objavljuj.
3. Grana od main, `git add <putanje>` (nikad -A), konvencionalni prefiks, testovi zeleni prije commita. PR veže `<DAN-xxx>` i ispravno `Risk:` prema `docs/ENGINEERING_SYSTEM.md`.
4. Nakon pusha: check-runs i statusi preko REST-a (kao u koraku 2), popravi crveno; `pnpm orch:overlap` i `pnpm orch:preflight <n>`; odgovori u nitima botova i Codexa (popravi ili obrazloži, D-110). Main u granu samo kod konflikta.
5. Prije SPREMAN sam napravi adversarijalnu provjeru: napiši popis „što bi reviewer i QA probali” (rubni ulazi, zaobilaženje, istodobnost, test koji ne dokazuje tvrdnju), provjeri svaku stavku i u opis PR-a dodaj odjeljak „Samoprovjera” s rezultatom za svaku.
6. Codex prije SPREMAN-a: nakon zadnjeg pusha objavi na PR-u `@codex review` i pričekaj Codex review na točnom headu (ponovljene jednokratne provjere `gh api repos/<repo>/pulls/<n>/reviews` otprilike svake 2 min između drugog rada, najviše ~20 min, bez sleepa). Odgovori u svakoj Codex niti (popravak ili obrazloženje) i razriješi je. SPREMAN javi tek kad na tom headu nema niti s `resolved: false` (`gh api repos/<repo>/pulls/<n>/ccr/review_threads`; nit razriješi s `gh api -X POST repos/<repo>/pulls/<n>/ccr/comments/<id>/resolve`). Novi push poništava ovaj korak i ponavlja ga, najviše 2 kruga; zatim SPREMAN s napomenom `Codex: 2 kruga, otvoreno <broj niti>`. Ako Codex ne odgovori u ~20 min, u SPREMAN poruci napiši `Codex: bez odgovora`.
7. Kad preflight prođe i korak 6 je gotov, na PR objavi `Spreman za review: <puni head SHA>` i na #1091 `OBLAK <slot> · SPREMAN #<n> <head>`. Kod blokade `OBLAK <slot> · BLOK` s razlogom. Na kraju `OBLAK <slot> · GOTOVO`.

## Pravila
Najviše dva kruga popravaka. Nakon prvog FAIL-a (review ili QA) sljedeći krug je suženi ugovor: samo nalaz iz FAIL-a, bez novog opsega. Ne pišeš retke Agent-Review, Review-*, QA-*, Owner-Override, Owner-Command ni Command-Head. Ne spajaš, ne pišeš na #87, ne mijenjaš tuđe PR-ove. Sigurnosne pojedinosti nikad javno, samo ID. Nema stvarnih osobnih podataka ni imena osoba s FPZG-a. Dokumenti u docs/ na hrvatskom, kod i commit poruke na engleskom. Odbijen `sleep` (i ulančani sleep) nije prepreka: ne ponavljaj ga, ne zaobilazi ga i ne objavljuj BLOK, nego nastavi s idućim korakom. Ako hook ili klasifikator uskrati bilo koju drugu radnju, stani i zapiši to na #1091, bez zaobilaženja.
